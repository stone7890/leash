3 · Invariants — 8 luật mọi chương phải phục tùng

I1–I7 giữ nguyên từ v1 (đã audit). I8 mới, sinh ra từ sandbox-first. Reviewer bác PR bằng cách chỉ số hiệu.

#LuậtVỡ thì mất gì
I1Non-custodial với treasury. Mọi tx động tới treasury (delegate, top-up, revoke) do ví owner ký. Leash không giữ tiền/khoá owner.Rơi vào diện money-transmission; mất định vị
I2Chain là nguồn sự thật ngân sách. DB là cache kèm last_read_slot; UI hiển thị số nào phải nói được đọc ở slot nào.Owner tin vào kiểm soát không tồn tại
I3Phân tầng cưỡng chế trung thực. Cứng on-chain: cap, expiry, revoke. Mềm tại Signer: allow-list, per-tx, velocity. UI bắt buộc dán nhãn tầng (ngôn ngữ thị giác: viền liền/chấm đặc vs viền đứt/chấm rỗng — chương 15).Sự cố đầu tiên phá uy tín sản phẩm an toàn
I4Không báo thành công sớm; unknown ≠ failed. Mọi ghi chain qua trạng thái chờ, chỉ thoát bằng read-back theo signature. Cấm retry bỏ qua bước đọc.Trả tiền hai lần cho một challenge
I5Kill switch sống sót khi Leash sập. Revoke là tx owner ký thẳng chain; docs công khai cách revoke bằng ví/CLI.Agent xổng chuồng đúng lúc cần dây cương
I6Tiền là số nguyên base unit. BIGINT micro-USDC ở DB, u64 ở protocol. Cấm float mọi tầng.Audit trail vô dụng vì lệch tích luỹ
I7Idempotency cưỡng chế tại storage. Ngoài: challenge_hash UNIQUE. Trong: Idempotency-Key UNIQUE. Retry trả kết quả cũ.Ký đôi một challenge = trả đôi
I8Sandbox và mainnet cách ly tuyệt đối. network gắn vào agent/allowance/payment từ lúc tạo, không đổi được (CHECK + cột immutable); API key prefix lk_test_/lk_live_; Signer từ chối challenge lệch network của agent key; RPC endpoint chọn theo bản ghi, không theo config toàn cục.Key test tiêu tiền thật — thảm hoạ niềm tin và tiền
Các trạng thái phải tách riêng (không đổi): allowance (pending/active/exhausted/expired/revoked) · payment (signed/submitted/confirmed/failed/unknown) · verdict (allowed/blocked) — cộng thêm trục mới độc lập: network (sandbox/mainnet). Gộp enum là lỗi data-model.

Bước hay bị làm sai nhất — N-12: cám dỗ là fake log test bằng frontend (như prototype). Bản thật phải chạy đúng vòng P2 qua endpoint mẫu trên Surfnet và stream log từ server (SSE trên GET /v1/test-payments/:id/stream); mỗi dòng log là một handshake_events thật. 9 · P2 — Vòng bắt tay 402 + timeline hạng nhất MVP

Bẫy trả-đôi (không đổi từ v1): retry cùng challenge phải nhận lại đúng payload cũ (khoá challenge_hash UNIQUE); payment kẹt ở submitted/unknown chỉ thoát bằng read-back theo signature — không bao giờ bằng ký lại.

Mới trong v3: mỗi bước của vòng này ghi một handshake_event — timeline trong drawer là dữ liệu thật, không phải render lại từ log

// 6 pha chuẩn của timeline (khớp UI drawer prototype v2)
type HandshakePhase = 'challenge_received' | 'rules_evaluated' | 'signed'
                     | 'replayed' | 'broadcast' | 'confirmed';
// Ai ghi pha nào: Signer ghi 1–3 (kèm kết quả từng rule S0–S7 vào detail jsonb);
// pha 4 'replayed' suy ra khi endpoint trả kết quả HOẶC bỏ trống (agent-side, không quan sát được — hiển thị mờ);
// Indexer ghi 5–6 từ read-back (kèm slot). Pha 'confirmed' CHỈ Indexer được ghi (I4).
// Blocked: timeline dừng ở pha 2 với failed_rule — đúng biến thể drawer 'blocked'.
// Unknown: pha 5 tồn tại, pha 6 chưa — drawer hiện spinner + giờ read-back kế tiếp.

Card từng bước nằm trong sơ đồ. Ràng buộc storage: one_payment_per_challenge, payments.signature UNIQUE (chương 12).

P4 — top-up / extend không khoảng chết

Trạng thái phái sinh trên UI: exhausted (cap rút hết, allowance vẫn active tới expiry — gợi ý top-up), expiring-soon (<24h — cột Expires cảnh vàng + alert nếu bật). Cả hai tính lúc query từ dữ liệu chain, không lưu.

P5 — kill switch hai tầng

Bẫy cửa sổ revoke (không đổi từ v1): giữa N-51 và N-54 tồn tại khoảng vài giây mà một agent gọi *thẳng* facilitator bằng payload đã ký trước đó vẫn settle được. UI phải giữ "revoking…" tới read-back N-55; với traffic đi qua Leash, S7 thu cửa sổ về ~0.

12 · Data model — 13 bảng; delta so với v1 khai ngay dưới DDL

CREATE TYPE network_t AS ENUM ('sandbox','mainnet');
CREATE TYPE allowance_state AS ENUM ('pending','active','exhausted','expired','revoked');
CREATE TYPE payment_state   AS ENUM ('signed','submitted','confirmed','failed','unknown');
CREATE TYPE verdict_t       AS ENUM ('allowed','blocked');
CREATE TYPE hs_phase AS ENUM ('challenge_received','rules_evaluated','signed','replayed','broadcast','confirmed');

CREATE TABLE orgs      (id uuid PK, owner_wallet text NOT NULL UNIQUE, plan text NOT NULL DEFAULT 'free',
                        active_network network_t NOT NULL DEFAULT 'sandbox', created_at timestamptz);
CREATE TABLE templates (id text PK, name text, prefills jsonb NOT NULL);          -- seed: research/scraper/blank
CREATE TABLE agents    (id uuid PK, org_id uuid FK, name text, template_id text FK,
                        network network_t NOT NULL,                              -- I8: trigger cấm UPDATE cột này
                        pubkey text NOT NULL UNIQUE, idempotency_key text NOT NULL UNIQUE,
                        killed boolean NOT NULL DEFAULT false, created_at timestamptz);
CREATE TABLE agent_keys(agent_id uuid PK FK, kms_key_ref text NOT NULL, rotated_at timestamptz);
CREATE TABLE allowances(id uuid PK, agent_id uuid FK, network network_t NOT NULL,
                        onchain_addr text NOT NULL UNIQUE, mint text NOT NULL,
                        cap_base bigint CHECK (cap_base > 0),
                        drawn_onchain_base bigint CHECK (drawn_onchain_base BETWEEN 0 AND cap_base),
                        expiry_ts timestamptz, state allowance_state DEFAULT 'pending', last_read_slot bigint);
CREATE UNIQUE INDEX one_active_allowance ON allowances(agent_id, mint) WHERE state IN ('pending','active');
CREATE TABLE policies  (agent_id uuid PK FK, allow_hosts text[] NOT NULL, allow_all boolean DEFAULT false,
                        per_tx_max_base bigint CHECK(>0), velocity_max_base bigint CHECK(>0),
                        velocity_window_s int DEFAULT 600);
CREATE TABLE policy_revisions(id bigserial PK, agent_id uuid FK, change jsonb, actor text, at timestamptz); -- append-only
CREATE TABLE sign_requests(id uuid PK, agent_id uuid FK, network network_t NOT NULL,
                        challenge_hash text NOT NULL UNIQUE, verdict verdict_t, failed_rule text,
                        checks jsonb NOT NULL,                                    -- kết quả từng S0–S7 cho timeline
                        requirements jsonb, created_at timestamptz);               -- append-only
CREATE TABLE payments  (id uuid PK, sign_request_id uuid FK, agent_id uuid FK, allowance_id uuid FK,
                        network network_t NOT NULL, signature text UNIQUE, pay_to text, host text,
                        amount_base bigint CHECK(>0), state payment_state DEFAULT 'signed', state_at timestamptz);
CREATE UNIQUE INDEX one_payment_per_challenge ON payments(sign_request_id);
CREATE TABLE handshake_events(id bigserial PK, payment_id uuid FK, phase hs_phase NOT NULL,
                        detail jsonb, read_back_slot bigint, at timestamptz NOT NULL); -- append-only; thay state_transitions của v1
CREATE UNIQUE INDEX one_phase_per_payment ON handshake_events(payment_id, phase);
CREATE TABLE alerts    (id uuid PK, org_id uuid FK, kind text, body jsonb, sent_at timestamptz);
CREATE TABLE suppressions(agent_id uuid FK, host text, created_at timestamptz, PRIMARY KEY(agent_id, host));
CREATE TABLE audit_jobs(id uuid PK, org_id uuid FK, range_from date, range_to date,
                        status text DEFAULT 'queued', url text);

REVOKE UPDATE, DELETE ON sign_requests, handshake_events, policy_revisions FROM leash_app;

13 · Contract design — tầng on-chain của Leash MVP

MVP không viết program mới: dùng primitive Subscriptions & Allowances đã audit. Chương này thiết kế adapter bao quanh nó, ma trận quyền, và fallback nếu [Q1] lệch giả định — tất cả cô lập trong packages/core/allowance-adapter.ts.

Interface adapter (ổn định với phần còn lại của hệ, bất kể [Q1])

interface AllowanceAdapter {
  // build tx CHƯA KÝ — chỉ ví owner ký (I1)
  buildCreate(p: {owner, agent, mint, capBase: bigint, expiryTs, network}): UnsignedTx;
  buildModify(p: {allowanceAddr, newCapBase?, newExpiryTs?}): UnsignedTx;   // P4 top-up/extend
  buildRevoke(p: {allowanceAddr}): UnsignedTx;                              // P5, cũng in ra docs revoke-tay (I5)
  // build + ký transfer rút trong allowance — chỉ Signer gọi, bằng agent key
  buildDraw(p: {allowanceAddr, agentKey, payTo, amountBase: bigint}): SignedTx;
  // đọc — chỉ Indexer/Signer-cache gọi
  readAllowance(addr): {capBase, drawnBase, expiryTs, state, slot};
}
